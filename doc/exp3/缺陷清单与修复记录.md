# 实验三 · 缺陷清单与修复记录

测试方式：MockMvc standalone（真实 Controller + 真实 Service，仅 mock 下游 DAO/Service）+ 53 条四类 Fuzzing 载荷。
判定口径：本项目 `GlobalExceptionHandler` 将所有未捕获异常转为 `errno=502`（HTTP 仍 200），故 **502 等价于"未捕获 500 崩溃"**。

## 一、已修复缺陷（6 类）

### D1 越权下单（IDOR）— 严重

- 位置：`WxOrderService.resolveCheckedGoodsList` / `clearCart`
- 现象：`cartService.findById(cartId)` 未校验 `cart.getUserId()`。userId=1 的用户提交 userId=999 的 `cartId` 可直接下单成功，并清空他人购物车。
- 修复前实测：`errno=0`，`orderService.add` 被调用 1 次。
- 修复：归属不匹配返回 `null`，`submit` 转 `ResponseUtil.unauthz()`（506）。
- 修复后实测：`errno=506`，`orderService.add` 调用 0 次。

### D2 负数商品数量 → 0 元订单 + 库存反向增加 — 严重

- 位置：`WxOrderService.calcCheckedGoodsPrice` / `deductStock`
- 现象：`number=-3` 使金额为负，`actualPrice.max(ZERO)` 兜底为 0 → 走 `handleZeroPayOrder`（payed=true）；同时 `reduceStock(productId, -3)` 执行 `stock = stock - (-3)`，**库存不减反增**。
- 修复前实测：`errno=502`（0 元订单链路中订单回查为 null 触发 NPE）。
- 修复：新增 `hasInvalidGoodsNumber()`，number 为 null 或 ≤0 在算价前拦截 → 402。
- 修复后实测：`errno=402`，`reduceStock` 调用 0 次。

### D3 未捕获异常：货品失效 / 库存扣减失败 — 严重（502）

- 位置：`WxOrderService.deductStock`
- 现象：购物车引用的货品已被删除，或并发下 `reduceStock` 影响 0 行时，直接抛 `RuntimeException`，被全局异常处理器兜成 `errno=502`。
- 修复：① 新增 `hasProductProblem()`，在建单**之前**校验货品存在与库存充足 → 402；② `deductStock` 调用处 try/catch，异常收敛为 505（数据更新失败），不再冒泡为 502。
- 修复后实测：失效货品下单 `errno=402`；扣减失败 `errno=505`。Fuzz 矩阵 502 数量由 8 降至 **0**。

### D4 NPE 多点 — 中（502）

| 位置 | 触发条件 | 修复 |
|---|---|---|
| `WxOrderService.goods` | 订单不存在即 `order.getUserId()` | 改用 `findById(userId, orderId)` 并判空 → 401 |
| `WxOrderService.comment` | `order.getComments()` 为 null 拆箱 | 加 null 兜底为 0 |
| `WxOrderService.handleZeroPayOrder` | 订单回查为 null | 判空 return |
| `WxCartController.add/fastadd/update` | `cart.getNumber()` 缺失即 `.intValue()` | 三处 `number == null → 401` |

### D5 参数类型不匹配导致异常泄漏 — 中（502）

- 位置：`JacksonUtil.parseInteger / parseShort / parseByte / parseBoolean / parseIntegerList / parseString*`
- 现象：请求体字段为数组、对象、null 时，`JsonNode.asInt()` 抛 `IllegalArgumentException`，而方法只 `catch (IOException)`，异常逃逸至全局处理器 → 502。
- 修复：`catch (IOException)` → `catch (Exception)`（10 处），解析失败统一返回 null，由调用方按"缺参"处理。
- 修复后实测：`cartId=[0]` → 401 / `addressId={"id":1}` → 401 / `cartId=null` → 401。

### D6 地址与购物车参数校验缺口 — 低

- `WxAddressController.detail` 的 `@NotNull Integer id` 在 standalone 下不生效（类级 `@Validated` 需 AOP 代理），缺 id 时落到 `query(userId, null)` → 402。生产环境由容器校验为 402，行为一致，仅记录差异。

| 类别 | 条数 | 契约内拒绝 | 业务码拒绝 | 正常受理 | 502 崩溃 |
|---|---|---|---|---|---|
| 类型混淆 | 18 | 7 | 0 | 11 | 0 |
| 极端数值 | 17 | 11 | 3 | 3 | 0 |
| 安全攻击（IDOR / SQL 注入） | 11 | 11 | 0 | 0 | 0 |
| 编码异常 | 7 | 3 | 0 | 4 | 0 |
| **合计** | **53** | **32** | **3** | **18** | **0** |

- 安全攻击类 **11/11 全部被拒绝**，无一例越权或注入被受理。
